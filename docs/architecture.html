System Architecture · End-to-End

Nabz نبض

A voice-first, Urdu-first AI health companion for Pakistani families. The browser captures speech and photos; a React SPA talks only to a FastAPI backend that owns every AI call, safety guardrail, and byte of patient data. Nabz runs an adaptive clinical interview, explains a non-diagnostic differential, routes to nearby care — and never states a diagnosis or invents a medicine.

Frontend React 18 · Vite · RTL · PWA Backend FastAPI · Pydantic v2 AI Qwen + Qwen-VL · DashScope Data SQLite · SQLAlchemy Care Location + ranked facilities Auth JWT · bcrypt
01

The request path, top to bottom

Every action flows down one spine: voice, photo or tap in the browser, through the React SPA, across a single JWT-authenticated JSON boundary, into FastAPI — which fans out to the Qwen models, a reverse-geocoder, the SQLite vault, and private file storage. AI keys and patient files live only below the boundary.

02

Adaptive interview → clinical synthesis

Nabz asks the single most useful complaint-relevant question at a time — a skin mark gets skin questions, not a reflex breathing question — accumulating a structured clinical_state. A red flag on any turn short-circuits to EMERGENCY. On conclusion it emits an explainable, non-diagnostic result.

03

The medication-evidence safety gate

This is why Nabz can suggest a medicine without prescribing one. The model only proposes candidate names and purposes; a server-side resolver is the sole writer of dose, evidence URL, and safety text — all drawn from a small curated catalog. Anything the model invents is dropped.

04

Location-first care routing

Location is a first-run input, not an afterthought — so every triage result can point to real, ranked facilities. The flow always answers, even on flaky Wi-Fi.

STEP 1

First-run gate

App withholds the workspace until a care location is set; the location screen stays editable later.

STEP 2

Resolve

/location/resolve reverse-geocodes lat/lon via Nominatim.

↳ offline → coarse PK-city lookup
STEP 3

Confirm

/location/confirm persists a LocationPreference (GPS or manual city).

STEP 4

Rank facilities

/facilities/nearby scores by severity-fit + type + real distance + verified + emergency capability.

05

Data model — the family vault

One account owns many patient profiles; everything hangs off a profile and is deleted with it (cascade). Personalization always pulls from the active profile alone. Location is stored per account; medicine evidence is derived at read time, never stored.

06

Response provenance & demo seeding

The running app is live-AI first. Every turn is stamped with a response_source so a safe outage reply or a test double can never masquerade as a real assessment.

Live path — live_ai

DASHSCOPE_API_KEY set
  • qwen-plus adaptive interview + synthesis
  • qwen-vl-plus for photos, labs, prescriptions
  • Guardrails + evidence resolver run outside the model
  • Timeout / bad output → safe fallback marked ai_unavailable

Offline & demo

no key · tests · one-click demo
  • pytest injects a test_model double — API contracts only
  • Live clinical behaviour still needs a real key
  • /api/demo/hassan seeds a synthetic longitudinal vault (mock-only, idempotent)
  • 4 watermarked fixtures · confirmed Cetirizine · low-Hb CBC · ibuprofen allergy

Safety boundary. Nabz triages urgency, explains a non-diagnostic differential, and reads documents — it never states a confirmed diagnosis, never authors a dose, and never delays an emergency to keep asking. Suggested medicines pass the §03 evidence gate; prescription scanning only transcribes an existing clinician's paper and requires human confirmation before saving.
