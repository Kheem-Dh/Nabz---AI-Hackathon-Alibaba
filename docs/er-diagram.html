Database · Entity-Relationship

Nabz Data Model نبض

SQLite via SQLAlchemy (swappable to Postgres/MySQL through DATABASE_URL). One account owns many patient profiles; clinical records hang off a profile; identity, consent and operational tables hang off the account. Uploaded files live in object storage — only their reference is kept here.

How & where things are stored

Identity & access

accounts, verification_codes — passwords are bcrypt hashes; OTP codes are HMAC hashes. Never plaintext.

Family vault

profiles → medicines / timeline_entries / triage_sessions. Personalization pulls from the active profile alone; cascade-deletes with it.

Uploaded files

Lab/prescription/scan images are not in the DB — stored in local uploads/ or S3 / Cloudflare R2 (encrypted). A timeline_entry holds only the reference in its JSON payload.

Care routing

location_preferences — one per account; coordinates kept only to rank nearby facilities, city/province persist.

Consent & audit

consent_records (versioned, append-only) and audit_events (privacy-safe security trail — no clinical text or file contents).

Operational

usage_sessions (owner analytics) and request_logs (method/path/status/latency only — no bodies, query strings, or tokens).
